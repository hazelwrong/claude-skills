# 综合评分 v3.1（满分 100）

只有未命中任何硬闸门的文章才进入这一步。逐模块打分并写出判断依据，不要凭整体印象直接给一个总分——尤其信息增量模块权重最高（25分），值得拆开六个子项认真打。

## 8 个模块

| 模块 | 分值 | 核心判断 |
|---|---|---|
| Google 抓取与页面基础 | 8 | 可访问、可索引、主体可渲染；H1、Title、基础 Schema 有且不严重冲突 |
| 搜索意图满足度 | 22 | 是否准确解决目标关键词背后的真实需求，是否兑现标题和引言承诺 |
| 信息增量与差异化价值 | 25 | 是否提供站内、竞品、通用 AI 内容之外的新数据、新分析、新场景或新决策价值 |
| 站内唯一性与重复风险 | 12 | 是否避免同意图重复，是否有清晰独立定位 |
| 商品与数据支撑 | 12 | 商品卡、价格、评分、规格、评论数、内部数据是否支撑结论 |
| 引用来源与出站链接质量 | 8 | 来源是否权威、相关、可访问；出站链接是否合理、安全、非竞品导流 |
| 合规与信任 | 8 | IP、YMYL、版权、作者/体验真实性、生成痕迹是否可控 |
| 发布体验与后续优化 | 5 | TD、UTM、alt、内链、面包屑、排版等可后改问题 |

## 总分 → 发布决策对照

| 总分 | 默认结论 | 入库 |
|---|---|---|
| 85–100 | 通过上线；若无软标签，进入发布无问题库 | 成功发布库 + 发布无问题库 |
| 75–84 | 可以上线；有软标签则进入发布后待优化库 | 成功发布库 / 发布后待优化库 |
| 65–74 | 先发后改；必须带优化标签和 SLA | 成功发布库 + 发布后待优化库 |
| 60–64 | 资深编辑复核；判断是先发后改还是不发重改 | 人工决定 |
| 0–59 | 不发重改 | 不发布待优化库 |

## 信息增量判断：闸门 + 打分

信息增量必须同时作为硬闸门（HG-3）和权重分（25分模块）。没有增量时不发；有增量但不够强时先发后改；增量高时直接发布并进入优质案例沉淀。

| 信息增量水平 | 判定标准 | 处理 |
|---|---|---|
| 无增量 | 只是复述旧文、SERP 常识、竞品内容或模板话术；没有新增数据、分析、场景、比较或决策建议 | 硬阻断，不发重改（HG-3） |
| 弱增量 | 有少量商品数据或场景建议，但不够具体；用户仍可能需要继续搜索 | 先发后改，打信息增量增强标签 |
| 中等增量 | 有清晰对比、内部数据、商品差异、适用场景或选择建议 | 可以发布，后续按优先级优化 |
| 高增量 | 提供独特数据、原创分析、第一手体验、清晰矩阵或强决策价值 | 直接发布，进入优质案例/模板库 |

### 信息增量 25 分的 6 个子项

| 子项 | 分值 | 评分说明 |
|---|---|---|
| 独立角度 | 5 | 是否区别于站内旧文和 SERP 主流结果 |
| 具体数据 | 5 | 是否有价格、评分、规格、评论、趋势、内部数据等具体支撑 |
| 分析深度 | 5 | 是否解释为什么，而不是只列是什么 |
| 场景/人群/预算适配 | 4 | 是否帮助不同用户做选择 |
| 决策可用性 | 4 | 读者是否能根据文章直接比较、选择或行动 |
| 新鲜度/更新价值 | 2 | 是否带来时间相关的新信息或更新理由 |

## 打分时的常见坑

- 不要把「文笔流畅」「结构清晰」当成信息增量高——信息增量看的是数据、分析深度、决策价值，不是表达质量。
- 搜索意图满足度（22分）和信息增量（25分）容易混着打：前者问"是否解决了这个关键词该解决的问题"，后者问"解决得比别人/旧文更好在哪"。两者可以一个高一个低。
- 60–64 分是刻意留出的临界区间，不要为了给出干脆结论就把 62 分之类的边界成绩硬凑到 65 或 59——如实打分，落在这个区间就明确标注需要人工复核。
